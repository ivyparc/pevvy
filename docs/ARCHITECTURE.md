# Foundation architecture

## 기술 기준

Expo SDK 57, React Native 0.86.3, React 19.2.3, TypeScript 6, Expo Router를 사용합니다. 공식 안정 템플릿과 SDK 호환성 검사를 기준으로 버전을 선택하고 직접 의존성과 잠금 파일을 고정합니다. pnpm 11 설정은 `pnpm-workspace.yaml`에서 관리합니다. `unrs-resolver`의 패키지 설치 스크립트만 허용합니다.

CI의 Expo 검사는 `EXPO_OFFLINE=1`로 설치된 SDK가 제공하는 호환성 목록을 검증합니다. 온라인 최신 패치 권장값이 바뀌었다는 이유만으로 이미 고정한 빌드가 실패하지 않게 합니다. 새 패치 업그레이드는 의존성 변경과 테스트를 함께 수행합니다.

화면 진입은 `src/app`, 화면 구성은 `src/features`, 재사용 UI는 `src/design`, 순수 계약과 규칙은 `src/core`에 둡니다. 화면에서 공급자 API를 직접 호출하지 않습니다. 아직 서버, 인증 세션, 실제 데이터 저장소는 없습니다.

## 내비게이션

각 탭은 독립 Stack입니다. Care의 안내 화면으로 스택 이동과 뒤로 가기를 확인할 수 있습니다. 설정은 루트의 모달 화면이며 디자인 시스템 화면은 공통 컴포넌트 점검용입니다. 앱의 `/` 진입은 설정을 불러온 뒤 저장된 마지막 탭으로 이동합니다. 실제 딥 링크는 저장된 탭보다 우선합니다. 시트는 Android `onRequestClose`와 웹 Escape 동작을 사용하는 공통 Modal입니다.

## 디자인과 국제화

색상·간격·모서리·글꼴·모션·최소 터치 크기는 토큰으로 관리합니다. 작은 흰 글자 버튼에는 브랜드색의 진한 변형 `#356B55`를 사용합니다. 플랫폼 시스템 글꼴과 글자 확대를 유지하고, 내용 영역을 스크롤할 수 있게 합니다. 모션은 이번 단계에서 기본적으로 없으며, 시트는 키보드 회피와 Safe Area를 적용합니다.

문자열은 타입으로 검증되는 영어·한국어 번역 사전에 둡니다. 날짜·금액은 Intl, 단위는 기준 값 kg/km/°C에서 변환합니다. 이벤트 시각은 UTC, 반복 일정은 IANA 시간대와 현지 시각, 생년월일은 날짜로 분리합니다. 앱 지역과 배송 국가는 서로 독립된 설정입니다. 초기 국가 선택 목록은 설정용이며, 해당 국가에서 상품·장소 데이터가 지원된다는 뜻이 아닙니다.

## 저장 경계

`SettingsRepository`는 버전이 있는 비민감 환경설정만 AsyncStorage에 저장합니다. 잘못된 JSON과 개별 필드를 검증하고, 쓰기를 직렬화해서 빠른 설정 변경의 이전 값이 마지막 값을 덮어쓰지 못하게 합니다. 저장 오류는 화면에 표시하며 현재 설정으로 재시도합니다. 인증 토큰·건강 기록·정밀 위치·문서는 이 저장소에 넣지 않습니다.

Pet별 캐시와 동기화는 `CacheStore`, `SyncQueue` 인터페이스로 분리했습니다. 구현은 Phase 2.0에서 인증 사용자별 저장 범위, 로그아웃 정리, 중복 방지, 충돌 보존을 포함해야 합니다. 이번 단계에는 돌봄 오프라인 기록이나 동기화 엔진이 없습니다.

`PetScope`는 All Pets 또는 단일 Pet입니다. All Pets는 조회 범위이며 기록 생성 대상이 아닙니다. `requireIndividualPet`가 이를 검증합니다. 이번 단계에서는 Pet 저장소가 없어 재시작 시 유효성을 확인할 수 없는 개별 선택을 All Pets로 되돌립니다. Phase 1.3에서는 실제 Pet 목록과 접근 권한으로 선택을 검증하고 복원해야 합니다.

## 데이터와 권한 계약

`Schedule`은 계획, `ScheduleOccurrence`는 예정된 실행 건, `CareLog`는 실제 수행 기록입니다. Pet ID, 실제 시각·서버 접수 시각, 작성자·수행자, 버전과 요청 ID를 분리합니다. 후속 구현의 완료 처리는 서버 트랜잭션과 재요청 중복 방지로 연결해야 합니다.

Owner·Caregiver·Viewer·Temporary Sitter는 명시적인 Pet별 capability 계약을 사용합니다. `canAccess`는 사용자·Pet 일치, 시작·만료, 권한 회수, 명시적인 capability를 검사하고 불명확한 요청을 거부합니다. 임시 시터는 만료 없는 권한을 허용하지 않습니다. **이 함수는 UI 판정용이며 보안을 구현한 것이 아닙니다.** Phase 1.1에서 서버 인증과 RLS, 역할별 capability 발급 규칙, 허용·거부 테스트가 필요합니다. 역할명만으로 모든 정보에 접근할 수 있다고 가정하지 않습니다.

## 외부 공급자

Places·Shopping·Notifications는 인터페이스만 제공합니다. 응답은 available / unsupported / unconfigured / error로 구분합니다. 미설정과 검색 결과 0건은 다른 상태입니다. 공급자 데이터의 출처와 확인 시각을 유지하고, 배송비를 모르면 null을 사용합니다. 결제·장바구니·배송 시스템은 PET의 범위가 아닙니다.

공급자 연동 단계에서 인증된 서버 경유, 지원 국가, 재게시·캐시·가격 이력 조건을 별도로 검증해야 합니다. 비밀 키를 앱에 포함하지 않습니다. 이번 단계에서는 분석·오류 추적 SDK와 민감 데이터 로그도 추가하지 않았습니다.
